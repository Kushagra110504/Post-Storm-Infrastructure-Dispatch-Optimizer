# GridRescue: Operator Walkthrough & Demo Guide

**GridRescue** is an interactive, control-room emergency response dispatch optimizer built on real OpenStreetMap data of Jaipur, India. It combines deterministic discrete-event simulation with **Hill Climbing (with Random Restarts)** to restore degraded municipal infrastructure following a severe storm.

---

## 1. Quick Start

```bash
# 1. Install dependencies
npm install

# 2. Run unit and integration tests (82 tests across 12 suites)
npm run test

# 3. Run automated optimization benchmark
npm run benchmark

# 4. Launch the interactive control-room web application
npm run dev
```

Open [http://localhost:5173](http://localhost:5173) in your browser.

## 2. Interactive Operator Walkthrough

### Step 1: Scenario & Map Exploration
1. **Interactive SVG Map**:
   - Pan and zoom across Jaipur's real road network.
   - Inspect 12 simulated incidents: 4 power faults (⚡), 3 water leaks (💧), 2 telecom outages (📡), and 3 road debris blockages (🚧).
   - Locate 8 specialized municipal crews (Alpha through Hotel) at their depots with authentic vehicle and equipment payloads (bucket trucks, pump vans, splicers, excavators).
   - Identify 5 critical protection targets (Sawai Man Singh Hospital, Jaipur Central Water Works, Pink City Telecom Core, etc.).
2. **Deterministic Seed Control**:
   - Try seeds `42`, `108`, or `999`. Each seed deterministically derives incident locations, skill requirements, dependencies, and guaranteed road blockages using Mulberry32 PRNG.
3. **Scenario Export / Import**:
   - Click **Export JSON** to download the validated scenario file.
   - Click **Import JSON** to paste and validate custom emergency scenarios guarded against prototype pollution and invalid graph coordinates.

### Step 2: Running the Nearest-First Greedy Baseline
1. Click **⚡ Run Baseline** in the header.
2. The greedy dispatcher evaluates nearest available crews, checks skill alignments, and routes crews along the network.
3. Observe the initial baseline KPIs:
   - **Makespan**: ~40–60 minutes
   - **Cost $J$**: Combined objective of total time, weighted hospital delay, and penalty for unresolved faults.
   - **Resolved Count**: Confirmed restoration of incidents.

### Step 3: Running Hill Climbing Optimization in Background Web Worker
1. Click **⛰️ Run Optimizer**.
2. **Zero UI Freezing (60 FPS)**: The optimizer runs decoupled in a Web Worker (`optimizer.worker.ts`).
3. **Neighbor Move Operators**:
   - `swap-team`: Reallocates tasks to better-suited or idle crews.
   - `swap-route`: Diverts crew paths to alternative routes (k=1..3) around bottlenecks.
   - `swap-order`: Optimizes execution order so road blockages are cleared before dependent repair crews arrive.
4. **Random Restarts**: Automatically resets with shuffled initial plans upon encountering local optima.
5. **Real-time Live Convergence Curve**:
   - View the live SVG chart tracking iterations vs. Cost $J$.
   - Red dots indicate initial baseline; green dots indicate steepest-descent improvements.
   - Review the **Comparison Table** showing quantitative delta across makespan, average resolution time, and overall cost reduction (typically **20% to 35% improvement**).

### Step 4: Inspecting Crew Schedules & Routes
1. Click the **Dispatch** tab in the sidebar.
2. Toggle between **Baseline** and **Hill Climbing** plans.
3. Review ordered crew dispatch cards and chronological simulation event logs:
   - `team-dispatched` → `team-arrived` → `repair-started` → `repair-completed` → `facility-restored`.

### Step 5: Dynamic Replanning Mid-Operation
1. Click **🔄 Replanning & Explain** in the header.
2. Simulate sudden emergency disruptions:
   - **⚡ Hospital Power Fault**: Injects a high-voltage transformer explosion directly degraded at the hospital.
   - **🚧 Block Arterial Road**: Simulates fallen trees cutting off a primary road artery.
   - **💧 Water Facility Burst**: Triggers an excavation-grade pipe rupture at the water facility.
3. **Warm-Start Optimization**:
   - Completed assignments prior to $t_{\text{now}}$ are locked as immutable history.
   - Active and pending tasks are dynamically replanned in <50ms.
4. **Plain-Language Explainability Narrative**:
   - Read the natural-language explanation generated by `explainPlanDiff`:
     - *Why crews were redirected or reassigned.*
     - *Which routes were diverted to bypass new blockages.*
     - *The net delta on hospital restoration time and total makespan.*

## 3. Command Reference

| Command | Description |
| :--- | :--- |
| `npm run dev` | Starts Vite development server at `localhost:5173` |
| `npm run test` | Executes full Vitest test suite (82 unit/integration tests) |
| `npm run benchmark` | Runs standalone engine benchmark (CLI throughput & cost delta) |
| `npm run typecheck` | Validates TypeScript compilation across browser and scripts |
| `npm run lint` | Runs ESLint on all codebase files |
| `npm run build` | Builds optimized, production-ready bundle in `dist/` |
